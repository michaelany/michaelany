# Project Instructions

Michael Any's portfolio is a responsive, accessible SPA and PWA built with
React 19, TypeScript, Vite, React Router, MUI, Sass and i18next. It supports English
and Russian.

Read and follow [Project Architecture](docs/architecture.md) and
[Code Style](docs/code-style.md) before changing project code. Task-specific user
instructions take precedence.

## Working Agreement

- Check comparable features first and reuse markup, styles and helpers that fit.
  Prefer the simplest approach that fits the project. Keep changes scoped and
  preserve unrelated edits. Add abstractions or dependencies for concrete needs.
- Install dependencies, format files, lint and start local servers as needed.
- Commit only when explicitly requested. Push, publish branches or tags, or
  create pull requests only if explicitly requested in the same turn.

## Validation

Run `npm run format:check` and `npm run lint` as appropriate. The user runs builds
and tests unless they explicitly ask you to run them. Mention any build or test
the change needs. Do not edit generated files in `dist/`.

## Maintaining the Docs

Record explicit user agreements, verified recurring conventions and confirmed
project changes. Keep each rule in the relevant document and keep this file
brief. Add a linked document only when an existing topic becomes hard to
navigate. Keep the working agreement intact and mention documentation changes
in the handoff.
